# S3 — connected model behavior and learned adaptation

Reviewed **22 October 2026, America/Chicago**. See the [master roadmap](00_Master_Roadmap.md), [current execution state](../../execution_state.md) and [dated primary-source review](07_Research_Evidence_20261022.md). Gates and budgets are proposed unless a linked existing report establishes execution. Planned artifacts below do not claim files already exist.

The current deterministic contract demo has a fixed symbolic compiler and task order. It demonstrates software transactions; it has not demonstrated learned neural self-improvement. S3 must connect actual model decisions, actual tool observations, actual bounded training and later independent outcomes.

The [proposed cognitive contracts](../experiments/20261022_Cognitive_Contracts.md) specify the typed bridge, task restart, evidence/cache/fast-state lifetimes, write authorities, director versions and identity/mode rules. They do not implement those mechanisms. Existing native small-sidecar forward/backward/export checks are narrower than this operating loop; the latest execution scope remains in [execution state](../../execution_state.md).

Freeze one declared developmental base, and hash-check it across every post-freeze cycle. Extensions and procedure skills change through independently evaluated candidates. Scoped evidence admission and private state have their own host-controlled transaction/update paths; they do not require neural candidate promotion. Evaluator/policy, human source identity and protected branch-goal authority remain outside candidate authority. The host executes validated proposals. Use a finite action/proposal grammar rather than generated arbitrary commands.

T0 persists nothing, T1 stores evidence, T2 follows fixed verified replay and T3 learns practice selection plus updates. Match experience opportunities and evaluation compute. A replay-matched T2 shadow control separates chosen data from update method; library growth and neural changes are separate measurements. The ten-cycle matrix must include failures, restart, deliberate rejection, rollback and no-improvement periods, with all learning/generation/verifier costs.

At migration, re-encode/rebuild incompatible state and recalibrate instead of carrying pilot latent state into the new system.

## S3.1 — Connect a frozen manifest to a host-owned runtime

**Status:** `partial_software_action_contract_preparation`. **Dependencies:** S2.5, S1.1 (unchanged for full completion).

For full selected-system completion, bind model inference to scoped evidence ledger, typed task workspace, permitted real tools and event journal after S2.5. Activate one identity mode and immutable base/extensions manifest; model output proposes actions but host code validates scope/budget and executes actual tools. Early fixed-baseline preparation above can proceed before that completion dependency.

The [bounded host action contract](../experiments/20261022_Host_Action_Contract.md), preregistered in `b2010c2`, now supplies strict `verify`/`answer`/`stop` proposals, host-stamped provenance, actual pure-XOR receipts and a canonical hash-chained journal. Its [fixture report](../../reports/host_action_contract_20261022/report.json) passes **12 actual host checks**, alongside **38 focused tests**. The host checks model-declared proposals against explicit scope, identity and budgets; a matching successful receipt from the current epoch is required to release an answer. Wrong-scope input, fabricated receipts, missing/malformed registers, budget excess and stale receipt/answer reuse are refused or recorded as actual failures. Duplicate actions and restart do not execute the tool again; source updates invalidate live receipts before cached answers can return.

These are deterministic software checks. No model is loaded and no neural proposer, training, learning or publication runs. Restart restores the static bound goal, recorded receipts and spent budgets; evolving goals, subgoals, hypotheses and next-action workspace remain pending, so the full task-restart gate is unqualified. Hash chaining checks integrity relative to a separately trusted head; it does not authenticate sources or erase historical source bytes. The fixture has no KV/recurrent/fast state to invalidate. Ask/retrieve/revise actions, actual model proposals and experience-to-learning integration remain pending. The existing untracked runtime draft is preserved separately.

- **Artifact:** implemented: bounded host action schema, pure-tool receipt boundary and deterministic restart/invalidation fixtures; planned: actual model-host adapter and full restart/scope/deletion integration report.
- **Interface:** Sense/route/core/inject/action proposal -> host validator -> real observation/verifier -> branch-owned experience -> ledger. Manifest binds base, tokenizer/processor, ports, writer/reader/core/action/calibration/director versions, task schema, identity and permissions. Decision state carries a pinned evidence revision.
- **Test gate:** Actual observations revise goals/subgoals/hypotheses; simulated outcomes stay hypothetical. Exact goal/action journal reconstructs the task after restart, rather than merely restoring records. Wrong-scope/expired records are hidden; selected-source invalidation/revocation blocks affected running output/actions and discards dependent workspace/KV/recurrent/fast state before rebuild. Base hash stays fixed. No generated text grants authority. Early-pilot results remain partial until selected-architecture binding passes.
- **Resources:** Local deterministic tools and CPU journal first; bounded MPS inference. Avoid arbitrary shell execution grammar.
- **Failure policy:** Reject invalid proposals without side effects and preserve trace. Repair host contracts before allowing autonomous candidate training.
- **Next smallest task:** Once the action-prompt protocol is qualified, predeclare one frozen-original M2 Ultra MPS proposal → host validation → actual pure-tool receipt → model-answer roundtrip with fixed decision, tool and generation budgets. Preserve actual malformed proposals and tool failures. This is the independent early pilot, not S2.4 architecture training; richer task state, experience-to-learning plumbing and S2.5 binding remain required for full completion.

## S3.4 — Learn useful practice selection against fixed replay

**Status:** `pending`. **Dependencies:** S3.2, S3.3.

Start with a short finite proposal catalog and supervised ranking/contextual bandit for practice selection. Version the director as `phi_director`, separately from action/calibration policy and protected evaluator/permission configuration. Reward later development/reward-role improvement with declared retention and cost penalties. Compare random/fixed selection and replay-matched controls before complex reinforcement learning.

- **Artifact:** planned: proposal/ranking dataset and director candidate; planned: selection-versus-update ablation report.
- **Interface:** Eligible branch experience/capability summaries/source pins -> director version -> bounded proposal with update target, generator, replay, parent and budget -> independent practice verifier -> candidate trainer. Proposed cadence selects at completed task/failure boundaries, holds versions fixed during comparisons, and evaluates at most one director-update candidate at a completed-cycle boundary. Director and skill candidates have separate manifests/costs.
- **Test gate:** Director cannot select audit examples, read hidden promotion labels, alter reward/verifier or escape task/budget whitelist. Predeclare reward gain, retention penalty and normalized generation/verifier/replay/training/evaluation costs; report raw costs and rejected candidates. Reward data are separate from independent promotion/final audit. Any T3 gain beyond fixed T2 survives replay-matched data and cost accounting; otherwise no useful selection claim.
- **Resources:** Small catalog, bounded number of proposals; count teacher generation, solver, training, replay and evaluator calls. No open-ended RL prerequisite.
- **Failure policy:** Keep fixed replay as baseline and record an inconclusive director if reward is noisy or improvements are indistinguishable.
- **Next smallest task:** Define three permissible practice targets, director parameter/version ownership, completed-cycle update cadence and fixed reward/cost weights; compute independent development-only learning-value labels.

## S3.5 — Run ten chronological T0/T1/T2/T3 learning cycles

**Status:** `pending`. **Dependencies:** S3.4.

Start all arms from the selected frozen parent and same permitted archive. T0 persists nothing, T1 records only, T2 fixed-schedule verified replay/candidates, T3 learned practice plus candidates. Include distribution change, no-improvement period, restart, rejection and rollback. Declare fast-state reset/persistence and evidence-revision policy identically across controls; default cross-request fast persistence is off.

- **Artifact:** planned: cycle-by-family performance/retention matrix; planned: chronological costs, exposure and publication history.
- **Interface:** Common experience stream -> arm-specific allowed persistent state -> matched later evaluation. T2 replay-matched shadow control isolates T3 data-selection effects.
- **Test gate:** Report all ten cycles, old/new family scores, forward transfer, forgetting, calibration, inquiry cost and rejection. Retain mode/identity/source/branch attribution, protected-goal continuity and revocation traces. T3 beyond T1 supports learning; T3 beyond T2 at stated budgets supports useful selection. Final audit remains unseen until reporting. A faithful source-belief prediction and a technically correct assistance outcome are scored separately.
- **Resources:** Ten initial bounded cycles; extend to 30–50 only after useful error bars/instrumentation. Match evaluation compute and disclose extra learning compute.
- **Failure policy:** Do not hide failed cycles or reset history after regression. Reject damaged candidates and preserve a valid negative/inconclusive longitudinal result.
- **Next smallest task:** Freeze the chronological stream, retention matrix and per-cycle resource/exposure budget before cycle 1.
