# Native D2 full-augmented qualification protocol

Declared 22 October 2026 before D2 optimizer updates. This advances
[S2.3](../stages/03_Native_Architecture_Study.md) and the D2 portion of
[S0.5](../stages/01_Environment_and_D0_Readiness.md). Outcomes belong in a separate
result record. The original D0 update-8 diagnostic remains selected; no
developmental or post-freeze model is promoted by this package.

## Fixed scope and execution

Use the existing sealed MiniCPM5-2B source revision
`f97400052a43d642bbc6e9975e2397e3ae6a6b52`, locked environment and native Llama
implementation. Fresh-source runs use seed 17. Regime `full_augmented` trains
all **2,516,756,480 originals in 381 tensors**, including embeddings/head, plus
**895,490 new parameters in 48 tensors**. No original layer is frozen.

Keep the measured 64-wide memory/workspace, four slots, two workspace steps,
four heads and final-block insertion. Support and original prompt context are
past-only and held fixed throughout each generated answer. Duplicate source
text stays in the native prompt. Use the qualified uncached generation route.

All native model computation uses **MPS GPU, FP32, CPU fallback disabled**,
microbatch one, accumulation eight and nonreentrant activation checkpointing.
Keep experimental Muon 8-bit momentum (block 2048, momentum .95, five FP32
Newton–Schulz steps, no Nesterov) and the declared FP32 AdamW exclusions.
Original Muon/AdamW peak rates are **1e-4**; new-module Muon/AdamW peak rates
are **1e-3**. Warmup is two updates, constant schedule, zero decay. These are
bounded diagnostic rates, not a fair architecture-rate study or production SFT.

Expected optimizer ownership is 294 original + 16 new Muon matrices and
87 original + 32 new AdamW tensors. Verify disjoint complete ownership and
actual mixed-state bytes rather than relying on these expected counts.

## Actual-length optimizer/capacity gate

Start with the existing exact 256-token train/dev capacity fixtures: eight rows
per split, prompt 254 tokens plus one answer and EOS. Every accumulated update
contains answers 0–7 once. Run two updates, split into fresh source→update 1,
completed-update checkpoint, then a new process resumed at 1→2. Save runtime
state every update and independently verify native base and sidecar reload.
The two-update schedule and all source/data/code settings must match on resume.

If 256 passes and disk space permits, repeat the same bounded two-process gate
at actual 512 tokens (prompt 510), starting fresh from the sealed source.
This closes S0.5 only if both D2 lengths pass. No training-quality claim follows
from these two updates. Capacity models are infrastructure probes and are not
parents of the tiny-overfit run.

Record original/new gradient coverage, changed native tensors, sidecar changes
between updates 1 and 2, optimizer dtypes/bytes, processed/support/supervised
tokens, phase timing, raw memory/host traces and native export/reload logits.
All 381 original tensors must receive finite nonzero gradients and show saved
changes. The first new backward is expected to reach only the two null output
projections; all 48 upstream tensors must receive signal after they open.

## Fresh-source balanced tiny-overfit gate

After 256 capacity passes, use the existing eight balanced mask-1 training rows
and 16 development fixtures, actual full sequence length 55 and ceiling 256.
Start fresh with the same scope, seed, rates and optimizer settings above.
The maximum schedule is **64 updates**. Stop the first process at update **4**
and save completed-update state; resume a fresh process toward the same total
budget. Set `checkpoint_every=16`: forced chunk-end/early-stop checkpoints
still preserve updates 4 and the eventual stopping update without writing a
full native checkpoint at every four-update generation check.

Generate all eight training answers every four updates, greedy, cap eight.
Stop after two consecutive checks with 8/8 strict correct and eight distinct
responses. Verify EOS/cap status separately. On no fit at 64, preserve the
negative without changing rates, scope or budget in that run. No conditional
rate search belongs to this protocol.

Evaluate the saved export in separate MPS processes on all train/dev rows.
Use the historical cap 256 if training answers terminate normally; otherwise
declare a short cap and do not equate unlike-cap scores. Keep raw tokens and
strict parser results. Memorization and development transfer are separate.

## Resource limits and evidence

Serialize full-size MPS jobs. Reuse the watchdog: driver limit 40 GiB,
sustained swap growth 512 MiB, minimum system free-memory reading 15%, three
host samples; retain its .25-second driver and two-second host sampling.
These sampled limits can miss transients. RSS and driver memory overlap.
Stop on nonfinite/scope/parity/pressure failures and preserve all reports.

Each capacity pair may add about 52 GB of logical checkpoint/export data.
Before a new length, require at least 80 GiB disk free; before the tiny run,
require at least 110 GiB for its bounded checkpoint policy. Identical immutable
native files may be compacted only by a byte-verified APFS copy-on-write clone;
never hardlink or alter their content. If physical space is not recovered,
leave the later gate pending rather than delete evidence or fill the disk.

Archive raw trainer/generation/profile/guard reports, checkpoint byte receipts,
source-normalized native tensor audits and sidecar continuation audits. Verify
current code hashes and contracts. Native restart is not a full-size
uninterrupted-versus-split numerical equivalence experiment. Complete this
package with updated stage status, remaining gates and focused local commits.

Matched useful architecture gain, retention, learned control/director,
authentic Replica fidelity, VLM, ANE execution and Blackwell residency remain
separate unqualified work. The early host-loop implementation is parallel
preparation and does not substitute for neural evidence.
