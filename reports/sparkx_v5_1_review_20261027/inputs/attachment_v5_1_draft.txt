# SparkX 2.6 4B — v5.1 refinement plan: multimodal capability, native multimodal memory, native multimodal reasoning and nested self-learning

**Version 5.1-draft · 27 October 2026 · Proposed revision to [Document 23](23_SparkX_2_6_4B_Final_Product_Blueprint.md) (v5.0).**

**Purpose:** This document corrects and refines the v5.0 blueprint using a structured review and a verified literature sweep. It is written for the workspace implementation agent. Each change is mapped to a v5.0 section, given a priority, tied to evidence and given a pass/fail gate (§11).

**Authority:** This is a *proposal*. It does not change executed receipts, admission records or Document 22's normative state/transaction contracts. Every new numeric choice is a **candidate** until it is preregistered and measured, which is the same convention v5.0 uses.

**Long-term goal:** A multimodal model built on Spark-X2.6-4B that can learn from experience in a nested way. The interfaces must carry over to larger future backbones (§10).

**Citation convention:** `[ShortName]` refers to §12. Every arXiv ID in §12 had its title checked against the arXiv abstract page or API on 2026-10-27. Numbers come from the abstracts unless marked **†**, which means the detail is from the paper body, reached via secondary sources, and should be checked in the PDF before anyone depends on the exact value.

## 1. Design principles carried forward and added

1. **Keep from v5.0:** claim discipline, information-removal audits (§16, §20.4), transactional state (§14.4), separation of stored, learned and deferred (§26.1), and teachers used offline only.
2. **New: train the way you deploy.** The chunk pattern, the memory read path and the inner update recipe used in offline training must be the ones that run in deployment ([StreamingVLM], [OML], [RLEdit]).
3. **New: evidence references are one type.** Points, boxes, temporal intervals, audio intervals and memory record citations share a single typed reference schema and a single reward family (§4.2, §6.3).
4. **New: diagnose before redesigning.** Every memory or learning failure is reported as separate addressing, readout and calibration numbers ([LongMemEval]).
5. **New: backbone-agnostic state where possible.** Store memory sensory features in encoder or fixed-width spaces so they can be re-projected for a new backbone (§10).

## 2. Multimodal capability refinements

### 2.1 Vision encoder, resolution and token budget (C1) — replaces v5.0 §4.1 vision row and §6.1

**Problem:** At 224 px with 64 tokens, SparkX sits 4–10× below every comparable ~4B VLM token budget. That conflicts with the "documents" contract and with fine pointing.

| Reference | Encoder / resolution | Tokens |
|---|---|---|
| [Gemma3]† (4B, sliding/global like Spark) | 400M SigLIP, 896×896, Pan&Scan | 256 per crop |
| [Qwen2.5-VL] | Native dynamic-resolution ViT, window attention | Dynamic (†2×2 merge) |
| [LLaVA-OV]† | SigLIP-So400m 384, AnyRes tiles | 729 per tile |
| [SmolVLM] | Aggressive pixel-shuffle compression wins for small models | Varies |
| v5.0 SparkX | SigLIP2-base 224 | 64 |

**Candidate reference (v5.1):**
- **Encoder:** `google/siglip2-so400m-patch16-naflex` (preferred) or `siglip2-so400m-patch14-384`. [SigLIP2] reports better localization and dense features than SigLIP at every scale, plus native-aspect NaFlex. Keep SigLIP2-base@224 only as the cheap ablation.
- **Tokens:** about 256 tokens per crop via 2×2 or 4×4 pixel shuffle, plus tiling or Pan&Scan for documents and small text. Budget 1 global view plus up to 4 detail tiles per image, and choose tiles from pixels and native queries, never from evaluation boxes (v5.0 §6.1 rule kept).
- **Connector:** keep the 2-layer MLP. [MM1] found connector design matters comparatively little next to resolution and token count. A 3D resampler over video frames is an optional arm ([MiniCPM-V4.5]).
- **Parameter impact (candidate):** about +300M encoder parameters over base. The projector input becomes 1152·s² (s = shuffle factor): about 18.4M parameters at s=2 (4608→2560→2560). v5.0 §1.1 already allows this, but §22.1 must be re-audited.

**Spark-specific caveats (must be tested):**
- **Sliding window 512:** in 27 of 36 layers, a multi-tile image (e.g. 5×256 = 1280 tokens) is only partly visible inside the local window. The 9 full-attention layers see everything. Measure whether tile order or a global-view-last ordering matters.
- **Bidirectional attention inside image spans** helped [Molmo2]. On Spark this means a mask edit inside media spans only, with causal attention everywhere else. Treat it as an ablation with disabled-extension parity preserved.

**Gate G-V1:** document/OCR and pointing development sets improve over base@224 at matched training compute. The 14-example memorization diagnostic must pass first (v5.0 O2; Review part 1 §4.1).

### 2.2 Media clock and positions (C2) — refines v5.0 §6.3 and §7.3

- **Textual timestamp tokens.** Insert `<t=12.0s>`-style tokens before each media chunk instead of a multi-axis RoPE. [Qwen3-VL] moved from T-RoPE to textual timestamps. Spark's layer-specific RoPE (partial 0.25 on full layers, full 1.0 on sliding layers) makes MRoPE-style surgery risky. Timestamps reuse the base tokenizer and keep the original positional computation unchanged.
- **Chunked AV interleave.** Within each ~2 s chunk, emit visual tokens then audio tokens, in time order across chunks ([Qwen2.5-Omni] TMRoPE†). This keeps the v5.0 `start/end/available_at` metadata, which becomes the source of the timestamp tokens.
- **fps-based sampling, not uniform-count sampling** ([Apollo]). Default 1–2 fps for coarse events, with dense re-sampling requests for detail (v5.0 §6.3 detail-request path kept).

### 2.3 Audio (refines v5.0 §7.1–7.2)

- **Rate:** about 10 tok/s is defensible. [Kimi-Audio] uses 12.5 Hz and [Qwen3-Omni]† uses 12.5 Hz; [Qwen2.5-Omni]† uses 25 Hz. Make **12.5 Hz the reference** (closer to proven systems) and keep 25 Hz as the fallback for fine acoustic tasks.
- **Fine-perception check:** [AV-Odyssey] DeafTest shows current models fail at basic loudness and pitch comparison. Add DeafTest-style probes to G-A1.
- **Alignment stage:** SPEAR is a self-supervised, non-text-aligned encoder ([SPEAR]). It needs a dedicated alignment stage (ASR + audio captioning + sound-event labels) before reasoning data. Whisper-based encoders ([Whisper], [Qwen2-Audio]) are text-aligned, multilingual and MIT-licensed. Keep a Whisper-encoder arm as a **co-primary candidate** for Mandarin and multilingual speech (v5.0 O3).

### 2.4 Training curriculum to protect text (C3) — replaces v5.0 §17.1 F1–F2 and §17.2 mixture

Evidence: progressive alignment works best when it moves from distinct modalities to bridging ones, with video as the bridge to audio ([Ola]). Adding speech can conflict with vision unless it is staged ([VITA-1.5]). Text-ability degradation is avoidable when text and multimodal data are mixed from early on ([Qwen3-Omni], [Kimi-Audio]). Fine-tuned MLLMs can even fall below their own vision encoder on recognition ([EMT]).

| Stage | Content | Trainable | Text share (charged positions) |
|---|---|---|---|
| F1 | Projector alignment: captions (PixMo-Cap), ASR, audio tags/captions | Projectors (+ pooling), backbone frozen | ≥20% |
| F2a | Images, documents, pointing/counting (PixMo-Points/Count/Docs) | Full: backbone + vision encoder | ≥30% |
| F2b | Multi-image and video: captions, QA, pointing, tracking (Molmo2 family), timestamps | Full | ≥25% |
| F2c | Audio: speech (EN + ZH), sound, music | Full: backbone + audio encoder | ≥25% |
| F2d | AV interleaved: dense AV captions → AV QA. Optional caption DPO ([video-SALMONN 2]) | Full | ≥25% |
| F2e | Grounded reasoning RL (§4) | Full or scoped | Text-only RL items included ([Omni-R1-A]) |

- **No memory or learning episodes in F2** (they move to F3/F4).
- **Text retention source:** self-distillation from frozen Spark-X2.6 over diverse prompts, including its thinking-budget modes and tool-call formats. Keep a retention gate on those behaviours.
- **Fallback:** if full fine-tuning breaks text retention beyond the gate, a modality-LoRA/router variant on a frozen LLM is a declared fallback ([Phi-4-MM]). It is not the reference.

### 2.5 Dataset deltas

The dataset and licence findings from Review part 1 are carried over. Additions supported by this sweep:
- **Molmo2 family** ([Molmo2]): VideoPoint, VideoTrack, Cap, AskModelAnything, VideoCapQA, MultiImageQA/Point (ODC-BY annotations). VideoTrack must be filtered per upstream source for the product lineage (e.g. MOSE is CC BY-NC-SA).
- **Visual CoT** ([VisualCoT]) for box-interleaved reasoning SFT; check its licence before admission.
- **CoTA-style structured audio CoT** ([Audio-Reasoner]), as research lineage unless licence-cleared.
- **OmniInstruct** ([OmniBench]) for tri-modal instruction data; check its licence.
- Keep the product/research lineage column from Review part 1 as mandatory.

## 3. Native multimodal memory

### 3.1 Diagnosis protocol first (C5) — prerequisite to all other memory work

[LongMemEval] decomposes long-term memory into **indexing, retrieval and reading**. Apply the same split to the current failure (21/384 correct, precision 21/138):

| Metric | Definition | Fix if low |
|---|---|---|
| R@16 | Gold record is among the ≤16 selected | §3.3 addressing |
| Oracle readout | Accuracy when the gold record is injected | §3.2 record content / literal tier |
| Risk–coverage curve | Precision as a function of the accept threshold | §3.6 calibration; threshold tuning first |

**Baselines (diagnostic only, not shipped):**
1. Gold facts in context.
2. Text RAG: BM25 + dense with token injection.
3. Long context up to 8k.
4. **Self-KV retrieval:** the model retrieves its own cached KVs ([ReKV]); this is the strongest training-free native baseline.

[MemT] reports parity with retrieval-augmented methods, not superiority. The native memory should be expected to *approach* text RAG first.

### 3.2 Multimodal record redesign (C7) — replaces v5.0 §8.2 feature payload

**Problem:** a single 256-d semantic vector plus 2×128-d visual and 2×128-d acoustic vectors cannot carry literals, and compresses modalities in isolation. Compressing each modality separately destroys cross-modal anchors ([Omni2LoRA]). Visual and audio memories need **separate budgets** ([OmniMem]). The strongest AV streaming memory uses a **modality-aware reader** ([video-SALMONN S]). External multimodal agents get large gains from **entity-centric** (face, voice, name) memory ([M3-Agent], +6.7/+7.7/+5.3 on its benchmarks).

**Candidate tiered record (all widths candidate):**

```text
ExperienceRecord v2
  identity / provenance / timing / geometry / state      # unchanged from v5.0
  address:
    dense_keys[M=4, 128]          # semantic, visual, acoustic, joint (multi-vector)
    lexical_sig[H=8 hashes]       # hashed n-grams of names/literals (Engram-style)
    entity_refs[<=4]              # entity_uid -> face/voice/name anchor embeddings
  compact_values:                 # always resident (v5.0 896 BF16 retained)
    semantic[256], visual[2,128], acoustic[2,128]
  hot_packets (hot tier only):
    visual_tokens[16, 512]        # projected from encoder features, not semantic summary
    audio_tokens[16, 512]
  literal_span: token_ids[<=32] + canonical-bytes ref   # verbatim copy tier
  joint_anchor: shared timestamp + entity links across modalities
```

**Byte budget (candidate, BF16):**

| Tier | Per record | Count | Total |
|---|---:|---:|---:|
| Compact (v5.0 features + metadata) | 2,304 B | 4,096 | 9 MiB |
| Multi-vector keys (4×128) | 1 KiB | 4,096 | 4 MiB |
| Hot packets (2×16×512) | 32 KiB | 1,024 hot | 32 MiB |
| Literal spans (32×4 B) | 128 B | 4,096 | 0.5 MiB |
| **Total** | | | **≈45.5 MiB** |

That fits inside v5.0's 256 MiB research envelope next to P (48 MiB) and its moments. Keeping hot packets for *all* 4,096 records would add 128 MiB and exceed it, so the hot tier is managed by the v5.0 §9.5 retention policy.

### 3.3 Hybrid native addressing (C6) — replaces v5.0 §9.2 steps 2–3

Evidence:
- Dense retrievers drastically underperform BM25 on simple entity-centric questions, and augmentation does not fix it ([EntityQs]).
- Dense+sparse hybrids were under-reported and are stronger ([DPR-Repl]).
- Engram's hashed n-gram lookup is O(1) and improves multi-query needle retrieval from 84.2 to 97.0 ([Engram]).
- A single model can emit dense, sparse and multi-vector scores ([BGE-M3]); late interaction beats a single vector ([ColBERTv2]).

**Candidate scoring:**
```text
s(q, r) = w_d · max_m <q_m, k_{r,m}>          # multi-vector dense (per modality)
        + w_l · |H(q) ∩ lexical_sig_r| / H     # hashed lexical overlap
        + w_e · 1[entity(q) ∈ entity_refs_r]   # entity anchor match
```
Weights are learned offline and frozen at release. Eligibility masks (scope, status, availability) apply **before** scoring (v5.0 rule kept).

**Training write/read alignment** ([REALM], [Atlas], [M+], [MemDecoder]):
- End-to-end reader loss plus an in-batch contrastive address loss against gold records (gold IDs only in the loss, never in routing, as in v5.0 §9.3).
- **Hard negatives:** same entity at a different time; same time in a different modality; superseded records.
- **Retriever distillation:** train the native address to imitate a strong external hybrid retriever's rankings, then evaluate it natively. [M+] shows a co-trained retriever extends retention from under 20k to over 160k tokens, where a latent pool alone collapses.

### 3.4 Read path: single-pass and chunk-delayed (C8) — replaces v5.0 §14.3 steps 3–5 as the reference

- **Query** from the hidden states of the **previous chunk** at an early layer (~L8–L11). Retrieve, then read at sites **deeper than the query layer** ([RETRO] chunked cross-attention; RETRO also shows a pretrained transformer can be retrofitted).
- **Read operator:** gated cross-attention with the original residual path preserved ([LM2]: BABILong +37.1% vs RMT, MMLU +5.0). A modality-aware reader uses separate projections per packet type ([video-SALMONN S]).
- **Sites:** v5.0's sites 3 and 7 come before the query layer, so they read only the workspace (and F if kept). Episodic reads start at site 11. The 9-site comparison in v5.0 §5.3 stays.
- **Training equals inference:** train with the same chunk-delayed pattern ([StreamingVLM]). The two-pass schedule stays as a correctness reference, not the default.
- **Literal tier:** when a record is selected, its `literal_span` tokens can be copied through a pointer/copy head over the literal tokens ([MemTrans]). Report it as episodic/literal recall, as in v5.0 §8.3.

### 3.5 Write path for streams (refines v5.0 §9.5)

- **Segmentation:** scene/event boundaries ([VideoLLaMB] SceneTiling) or surprise-based boundaries ([EM-LLM]), instead of fixed windows. A fixed-span writer stays as the baseline.
- **Saliency without the question:** query-agnostic compression scored against generic query tokens ([StreamMem]). Deduplicate near-identical frames ([LongVU]).
- **Consolidation:** short-term → long-term merging of duplicates and entity-record updates ([MovieChat], [TeleMem]).
- **Asynchrony:** the writer runs separately from the answerer ([Flash-VStream], [Dispider]). This fits v5.0's one-writer-per-scope transaction model.

### 3.6 Calibration and abstention (refines v5.0 §9.2 step 4)

Models hallucinate even when the context is sufficient. Sufficiency-guided selective generation adds +2–10% accuracy on the questions answered ([SufficientCtx]). Retrieval matters most for long-tail entities ([PopQA]).

**Abstention-head inputs:** top-1/top-2 score margin, lexical-hit flag, entity match, cross-modal agreement between the visual and acoustic packets, and the parametric-confidence estimate. Train refusals on episodes where the gold record is ineligible or evicted ([Trust-Align]).

### 3.7 Fast memory F (C9) — demotion

[TTT-E2E] shows Mamba2 and Gated DeltaNet do **not** scale with context the way full attention or TTT-E2E do (3B, 164B tokens). The v5.0 F is an ungated delta rule. Its gated variant is strictly better ([GatedDeltaNet]), and window-level optimization beats per-token updates ([ATLAS]).

**Decision:** remove F from the v5.1 reference and keep it as arm `M-F`. If it is revived, use a gated delta rule or a TTT layer with a long-span objective ([video-SALMONN S]), with chunk-level updates. It must beat E-alone under reset and wrong-state controls.

### 3.8 Optional parametric fact layer

Memory layers beat dense models with twice the compute, with gains largest on factual tasks ([MemLayers]); ultra-sparse memory scales favourably ([UltraMem]). The plastic bank P (§5.3) can be implemented as a **product-key memory layer** ([PKM]), which also gives fine-grained sparse writes.

## 4. Native multimodal reasoning (C4) — replaces v5.0 §6.4 and moves part of §18.1's "later branch" earlier

### 4.1 Evidence that this works at Spark's size

- **4B:** point/box-grounded thinking with dense grounding rewards lets Gemma3-4B-IT match or exceed Gemma3-27B on spatial reasoning ([TwVG]).
- **3B:** a 3B VLM trained with GRPO and mixed perception+cognition rewards reached #1 on the Open LMM Reasoning leaderboard ([SFTorRL]).
- **Small data:** box-interleaved reasoning works with as few as 20 samples using answer+format reward ([GRIT]). A 3K SFT cold start plus RL gives +5% on V* ([CoF]).

### 4.2 Unified evidence reference (extends v5.0 §6.2)

```text
EvidenceRef = {kind: point|box|interval|audio_interval|record,
               source_id, frame_id|t_start..t_end, xy|xyxy, record_uid?, confidence}
```
A reasoning step may cite any `EvidenceRef`. Memory citations (`kind=record`) let memory-grounded reasoning use the same mechanism as visual grounding (§6.3).

### 4.3 Training recipe

| Step | Data | Objective | Evidence |
|---|---|---|---|
| R0 cold start (light) | Box/point CoT ([VisualCoT], PixMo, Molmo2); structured audio CoT subset ([Audio-Reasoner]) | SFT, a few thousand to ~165k items | [CoF], [Video-R1], [SFTorRL] (heavy SFT locks in imitation) |
| R1 image grounding RL | Counting, spatial relations | GRPO: answer + point-match / box-IoU **dense grounding reward** | [TwVG], [GRIT], [DeepEyes] |
| R2 temporal RL | Temporal grounding, ordering | Temporal IoU reward; T-GRPO temporal contrast (shuffled-frame comparison) | [Time-R1], [Video-R1], [VideoChat-R1] |
| R3 audio RL | MMAU-style audio QA | GRPO. **Thinking optional**, since explicit reasoning gave no significant gain | [R1-AQA] |
| R4 AV RL | AV counting, source localisation | GRPO + clue/timestamp grounding reward; coarse-to-fine | [AV-Reasoner], [Omni-R1-2S], [EchoInk-R1] |
| R5 memory-grounded RL (after F3) | Delayed AV questions | Answer + correct `record_uid` citation + interval/box grounding (gold IDs only in the reward) | Proposed synthesis of [TwVG] + [M3-Agent] |

### 4.4 Guardrails

- **Modality-reliance audit:** report full / audio-only / video-only / text-only accuracy ([Daily-Omni]). Text-only fine-tuning can raise audio scores ([Omni-R1-A]), so gains need ablation proof. Language-space reasoning alone gave no out-of-distribution gain on AV counting ([AV-Reasoner]), so require clue grounding.
- **Decorative-reference check** (v5.0 §6.4 kept): a box that is not linked to source features earns no grounding reward.
- **Latent visual tokens:** optional after explicit grounding works. Budget ≤20 continuous tokens ([CoVT]: about 20 tokens, +3–16%). Alternative objectives: [LVR], [Mirage-MI].
- **Text-only RL items** stay in the mix to preserve reasoning ([Omni-R1-A]).

## 5. Nested self-learning (C10–C14) — replaces v5.0 §10.3–10.6

### 5.1 P0 bug: persisted momentum (C10)

With β₁=0.9 and moments persisted across events (bias correction ≈1), the first step on a new fact B is `0.9·m_A + 0.1·g_B`. The new fact contributes about 10% of step 1 and about 19% after two steps.
- Carrying Adam state across shifting objectives contaminates updates, and resetting helps ([AdamReset]).
- Nested Learning treats optimizer momentum as a memory of gradients ([NestedLearning]), so persisting it mixes facts together.
- Most early-step damage shows up as lost alignment ([SpuriousForget]).

**Fix:** set `m ← 0` at each teaching event. Keep `v` as a slow preconditioner (frozen EMA), or replace the step-size rule with meta-learned Meta-SGD step sizes (§5.6). Continued-learning parity (v5.0 §15.2) persists `v`, the counters and α only.

### 5.2 Store now, consolidate later (C11)

Evidence against few-step online writes:
- New-knowledge examples are learned slowly and, once learned, increase hallucination ([Gekhman24]).
- RAG beats fine-tuning for knowledge injection ([Ovadia23]).
- Facts written without augmentation get 0% question-extraction accuracy ([PhysLM3.1]).
- "A is B" training does not teach "B is A" ([ReversalCurse]).

Complementary learning systems theory predicts exactly the split below ([CLS95], [CLS16]), and recent LLM work implements sleep-like consolidation ([LMSleep], [SleepCompute]).

```mermaid
sequenceDiagram
  participant U as Teacher (trust tier)
  participant E as Episodic E
  participant G as Derived-example generator
  participant Pf as Pf (fast plastic)
  participant Ps as Ps (slow plastic)
  U->>E: commit record (instant recall; receipt "stored")
  alt tier allows parameter learning
    E->>G: teaching + media
    G->>G: K=8-16 derived examples, entailment filter
    G->>Pf: gated sparse-write self-distillation (4-8 steps)
    Pf->>Pf: free-generation probes + anchor KL check
    Pf-->>U: receipt "learned (fast)" or "stored only"
    Note over Pf,Ps: idle time or every 16 eligible events
    Pf->>Ps: consolidation (replay + original sources, EWC, LR rewarm/decay)
    Ps-->>U: receipt "consolidated"
  end
```

### 5.3 The write objective and update rule (C11, C12)

**Augmentation (mandatory).** For each eligible teaching event, generate K=8–16 derived examples: paraphrases, **both directions**, QA form, multi-hop items using known facts, and for multimodal facts, cross-view, crop and caption variants. Evidence:
- Diverse synthetic renderings: QuALITY 39.49 → 56.22† ([EntiGraph]).
- Self-generated study strategies: +313% relative on SimpleQA-Wiki ([ActiveReading]).
- Self-edits: 33.5 → 47.0† ([SEAL]).
- Generate per fact, not per document ([SFT-Inject]). QA before statements ([PIT]). Multi-hop propagation needs explicit training ([MQuAKE]).

**Entailment rule.** A derived example inherits "verified" status only if the frozen base model *with the teaching in context* judges it entailed. It is tagged `derived` and revoked with its parent. Replay always includes the original verified sources, because accumulating real plus synthetic data avoids collapse while replacing it does not ([Accumulate], [Collapse23]).

**Objective: self-distillation, not next-token loss.**
- Teacher: the frozen model *with the teaching (and its media) in context*. Student: model + candidate Pf *without* it.
- Loss: KL over the derived queries' responses ([Cartridges]: self-study matches in-context learning where plain next-token training does not; [SDFT26]: on-policy self-distillation forgets less; [RLRazor]: forgetting tracks forward KL, so a KL-minimal write forgets least).

**P read/write structure:**
- **Dense read:** all experts in a pool read through a soft gate. All 16 experts at 9 sites cost about 113M MAC/token ≈ 2.75% of the backbone, so top-1 routing isn't worth its failure mode.
- **Sparse write:** update only the top-r rows of each expert's **gate/up** matrices, ranked by activation on the teaching relative to background usage ([SparseMemFT]: NaturalQuestions F1 drop 11% vs 89% full FT vs 71% LoRA). Keep **down** frozen or slow ([LMM-Skills]: gate&up only +30.5 learning / −2.1 held-out, vs full LLM +31.8 / −23.3). Candidate r ∈ {32, 128, 512}.
- **Null-space projection per site:** project ΔP onto the null space of a running covariance of preserved keys from the anchor and replay activations ([AlphaEdit], [Adam-NSCL], [GPM]).
- **Closed-form arm:** clean (subject, relation, object) facts can be batch-inserted into Ps during consolidation with MEMIT/UltraEdit-style updates under AlphaEdit projection ([MEMIT], [UltraEdit]). Everything else uses the gradient arm.

**Anchor:** add `λ·KL(base ‖ base+P)` on about 64 anchor prompts per event, covering general text, instruction following, thinking-mode format and **visual/audio recognition probes** ([LwF], [RLRazor], [CoIN], [EMT]). The write is rejected if the KL budget is exceeded.

**Commit gate:** 3 held-out derived questions, answered by **free generation, not teacher forcing**. Teacher-forced evaluation inflates editing success to 96.8% versus 38.5% in the wild ([Mirage-Edit]). The write commits only if the probes pass and the anchor KL is within budget; otherwise it rolls back to "stored only".

### 5.4 Candidate per-event inner recipe (replaces v5.0 §10.4)

```text
1  admit: tier check; write E (always); T3 stops here
2  augment: 12 derived → entailment filter → keep ~8 (≥2 reversed, ≥2 multi-hop, cross-modal if media)
3  optimizer: m ← 0; α from Meta-SGD (per group, per step); v frozen
4  Pf write: 4–8 steps; minibatch = 8 derived + 8 replay + 4 anchors
            loss = KL_selfdistill + λ·KL_anchor; grad masked to top-r gate/up rows; null-space projected
5  gate: free-generation probes + anchor KL budget → commit or rollback
6  consolidate (idle or every 16 eligible events): replay queue + reservoir + original sources
            → distill into Ps; closed-form batch for clean triples; EWC on Ps; LR rewarm→decay
            → Pf ← P0 + γ(Pf − P0), γ≈0.5
```

**Budget change (must be declared):** v5.0's "≤256 positions and ≤4 steps per boundary" cannot accommodate augmentation plus anchors. Candidate: about 1–1.3k positions per step × 4–8 steps, plus about 12 short generations per event. That is roughly 10–30k forward-equivalent positions per event. It meets the v5.0 "≤10% amortized learning time" target only on sparse-teaching workloads, which is why writes are deferred to idle time ([SleepCompute]). Measure it.

### 5.5 Consolidation and long-run health (refines v5.0 §10.1 clocks)

- **Clock mapping:** Pf is the per-event gated write; Ps is consolidation (idle or every 16 eligible events). Together they form the two-frequency spectrum that [NestedLearning]'s Continuum Memory System describes. This is not a HOPE reproduction (the v5.0 disclaimer stays).
- **LR schedule:** consolidation uses rewarm then decay, plus replay ([CPT-Replay], [Rewarm]).
- **Monitors:**
  - Sequential edits forget gradually, then collapse abruptly ([EditForget]). Track the P norm, anchor KL and probe recall per 100 events, and trigger consolidation or reset on drift.
  - Plasticity is lost over long training ([LossPlasticity]). Monitor dead or saturated Pf units and reinitialize them toward P0.
- **Sharding:** Pf shards are merged into Ps, matching the side-memory/sharding design in [WISE].

### 5.6 Meta-training to learn (C13) — replaces v5.0 §10.5 estimator

| Element | v5.0 | v5.1 candidate | Evidence |
|---|---|---|---|
| Inner loop | ≤2 AdamW steps, persisted moments | **Exactly the §5.4 recipe** | [OML], [RLEdit] |
| Episode | ≥32 events | T=16–32 events: new facts, counterfactual edits, multimodal entity facts, ~10% poisoned/unverified events labelled "do not write" | [Gekhman24] curriculum: known → new |
| E during outer loss | Present | **Dropped in p=0.5 of episodes**; ≥30–50% of outer queries P-only | Review part 2 §3.4 |
| Meta-learned | P0 | P0 + **Meta-SGD α** (per group, per step) + **ANML-style write gate / row selector** + anchor λ | [Meta-SGD], [MAML++], [ANML] |
| Estimator | First-order, identity Jacobian | Reptile/FOMAML for P0; **truncated second-order through the last 2 inner steps** for α and the gates | [Reptile], [MAML++] |
| Outer loss | Future query + retention + grounding | + reverse/multi-hop recall + backward-forgetting penalty + poisoned-event compliance + anchor KL | [MQuAKE], [EditForget] |
| Parallel arm | — | **Amortized writer:** hypernetwork maps teaching to a Pf delta in one pass | [D2L], [GenAdapter], [T2L], [MEND] |
| Later arm | — | Augmentation policy trained with the post-update reward | [SEAL] |

**Cost honesty:** each episode costs roughly T × (10–30k) forward-equivalents, about 0.2–0.9M positions per episode. Pre-generate the augmentations offline with teachers (allowed by v5.0 §17.3). Do the first runs on MiniCPM and count every inner position in §22.5 (Review part 2 §3.8).

**Evidence that this works at LLM scale:** a meta-learned initialization for test-time weight updates scales like full attention at 3B ([TTT-E2E]). Hypernetwork writers internalize context in a single forward pass ([D2L], [GenAdapter]: +63.5% on StreamingQA).

### 5.7 Trust, poisoning and rollback (C14) — extends v5.0 §10.6 and §15.3

| Tier | Source | May write |
|---|---|---|
| T1 | Operator-signed or tool-verified | E, Pf, Ps |
| T2 | User corrections confirmed ≥2 times, consistent | E, Pf (expiring) |
| T3 | Unverified text; **all instructions embedded in media** | E only (tentative) |

- About 250 poisoned documents can backdoor models from 600M to 13B regardless of clean data size ([Poison250]). Apply per-source and per-scope rate limits on Pf/Ps writes.
- Memory can be poisoned through queries alone ([MINJA]), and retrieval keys can be backdoored ([AgentPoison], [PoisonedRAG]). Detect address anomalies, and never treat teaching content as instructions ([IndirectPI]).
- Images and audio can inject instructions ([ImgInject], [VisJailbreak]), which is why media-embedded instructions are tier T3.
- Backdoors survive later training ([SleeperAgents]). Keep **rollback snapshots** of P plus `v`: about 96 MiB each without `m` (48 MiB P + 48 MiB v). Eight snapshots cost about 768 MiB of disk, and replay after removal is bounded by the snapshot interval.

## 6. Combining modalities, memory and learning natively

### 6.1 Multimodal teaching events

- **Derived examples for sensory facts:** new crops and views, a different speaker or performer, time-shifted audio, a caption-only and an audio-only rendering, and reversed queries ("which device shows a blue pulse?" ↔ "what does the blue pulse mean?").
- **Self-distillation teacher** sees the media + teaching in context; the student sees new instances without it (§5.3).
- **Evaluation:** editing multimodal LLMs is harder than text-only ([MMEdit]). Use [VLKEB] (portability) and [MIKE] (fine-grained entities), plus owned AV rule worlds (v5.0 §16).

### 6.2 Entity-centric multimodal memory

Face, voice and name anchors link records across modalities and time ([M3-Agent]). Identity recognition is the bottleneck in egocentric assistants ([EgoLife]). The **entity_refs** address component (§3.3) and the record's joint anchor (§3.2) implement this natively. Personal-identity data must carry consent and scope flags; this is a product requirement rather than a research result.

### 6.3 Memory-grounded multimodal reasoning

Retrieved records act as **evidence references** (§4.2). A reasoning step can cite `record_uid` plus an interval or box inside that record's source, and RL step R5 rewards correct citation. This unifies "thinking with visual grounding" ([TwVG]) with episodic recall. It is a **proposed synthesis**, not an established result.

### 6.4 Episodic learning from video

Use **ELViM** (learning from video seen hours earlier, inside [video-SALMONN S]) and **M3-Bench** ([M3-Agent]) as external tests that the combined E+reasoning path works on long AV streams.

### 6.5 Revised worked example (v5.0 §16)

| Step | v5.1 behaviour |
|---|---|
| Observe | Chunked AV interleave with timestamps. A scene-boundary writer creates the record: hot visual and audio packets, entity ref for the device, literal span for its name |
| Teach (T1) | Instant E commit → receipt "stored". 12 derived examples (new device colours, reversed queries, audio-only variant) → entailment filter |
| Adapt | Pf self-distillation, sparse write, anchor KL check, free-generation probes → "learned (fast)" |
| Consolidate | Idle-time Ps distillation + EWC → "consolidated" |
| Query a new device | Single-pass read: hybrid address hits the entity + lexical signature. The answer cites `record_uid` + interval |
| P-only audit | E/F/C/prompts/KV removed (v5.0 §16 audit unchanged). Gain must persist |
| Poison test | A T3 user claims the opposite rule 300 times → E only, rate-limited, no Pf/Ps change |

## 10. Scaling contract for larger future backbones (C16)

**Evidence:**
- Design decisions made at small model and data scale transfer to larger models up to a critical size ([Apollo]).
- Encoder size can scale with the LLM and save data ([InternVL2.5]†).
- Connector design matters little and the recipe scales to 30B ([MM1]).
- Model families share one encoder across sizes ([Qwen3-VL] 2B–235B, [Gemma3] 4B–27B).
- Memory layers and hashed lookup scale to 128B memory parameters and 27B models respectively ([MemLayers], [Engram]).
- Late versus early fusion shows no inherent advantage ([NMM-Scaling]).

**Contract (design rules):**
1. **Width-relative interfaces:** reader width ≈ d_model/5, packet width fixed at 512, plastic width fixed at 256. Only the down/up projections depend on d_model.
2. **Memory sites follow the full-attention layers** (Spark: every 4th). For MoE backbones, read at attention sites and keep P as a separate memory layer, not per-expert.
3. **Backbone-agnostic memory features:** hot visual and audio packets are derived from *encoder* features at a fixed 512 width. Semantic keys are re-derivable. During release migration, re-project rather than discard where a trained migration map passes the v5.0 §15.4 tests.
4. **Encoder growth path:** keep So400m for 4B–30B. Consider SigLIP2-g (1B) for ≥30B ([SigLIP2] sizes; [InternVL2.5]†).
5. **Two-size confirmation:** every mechanism decision is confirmed on MiniCPM (2.5B) and Spark (4B) before the full Spark campaign. That is a cheap scaling-consistency check ([Apollo]).
6. **Open risk:** no verified paper shows an episodic *multimodal* memory transferring from 4B to larger backbones. Treat it as an experiment.
