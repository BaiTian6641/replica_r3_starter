# Independent audit batch — 30 October 2026

Status: read-only audits, no native job, no development-label reads. This document preserves the findings before another repair round. No finding is silently treated as a pass.

## Research evidence and design consequence

- [Lee et al., ACL 2022, §5.2–5.3](https://aclanthology.org/2022.acl-long.577.pdf): name-swapped templated examples are near-duplicates; train/test overlap inflates evaluation and biases model selection.
- [Søgaard et al., EACL 2021](https://aclanthology.org/2021.eacl-main.156.pdf): random splits systematically overestimate performance; independent/adversarial splits are required.
- [Keysers et al., ICLR 2020](https://arxiv.org/pdf/1912.09713): generalization depends on holding out compounds/dependency units, not merely atoms.
- [Kapoor and Narayanan, Patterns 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10499856): splits must account for dependencies between training and test units.

The current v12 development generator changes entity names, order, unknown positions and palette, but uses the same two rule families, oracle and templates. It is a fresh same-family draw, not an independent rule-family evaluation. A native utility claim requires a compound/rule-family holdout or an explicitly narrower claim.

- [Moyer, Ensuring data reaches disk](https://lwn.net/Articles/457667/): temp file → write → file fsync → rename → parent-directory fsync.
- [SQLite atomic commit, §5](https://sqlite.org/atomiccommit.html): multi-file transactions need a super-journal and an explicit commit point; a sequence of renames is not a multi-file transaction.
- [Apple fsync(2)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html): plain `fsync()` does not guarantee drive-cache flush; `F_FULLFSYNC` is the tighter Darwin mechanism, with filesystem/device caveats.
- [POSIX rename](https://pubs.opengroup.org/onlinepubs/9699919799/functions/rename.html): atomic per-name visibility, not multi-file atomicity or media durability.
- [PyTorch MPS synchronize](https://docs.pytorch.org/docs/2.14/generated/torch.mps.synchronize.html): waits for all kernels in all streams on an MPS device. It does not prove device locality when CPU fallback is enabled.
- [PyTorch MPS environment variables](https://docs.pytorch.org/docs/main/mps_environment_variables.html): `PYTORCH_ENABLE_MPS_FALLBACK=1` permits unsupported ops to run on CPU.

Navigation needs one validated authority pointer and crash/restart resolution, not only exception rollback. Density native timing must enforce `PYTORCH_ENABLE_MPS_FALLBACK=0` and distinguish end-to-end wall time from kernel time.

## Native budget audit

Confirmed sufficient for the fixed protocol:

- Read bound `3 + 2×4 = 11` writes; actual same-process descriptor writes are at most 7.
- Final probe bound `32×(4+11) + 2 + 1 + 1 = 484`, exactly consumed by the fixed success path.

Confirmed open defects:

1. Release-origin `current.json` and lock creation occur before rebuild reservation and outside native write accounting.
2. Rebuild pointer reads, manifest hashing and rollback reads bypass release read accounting.
3. The 9 MiB direct-read bound undercounts 4–7 manifest reads per world; 24–28 MiB worst-case authority reads can exceed it. Restart/load/teacher-cache/config/template/data reads also occur before reservation or with zero `artifact_read_bytes` allocation.
4. Persistence-failure fallback can add an uncharged physical descriptor write.

## Durability audit

- O1: origin rollback can leave live pointer with refunded charge; real post-replace failure cleanup is untested.
- O2/O3: cleanup unlink/replace failures can mask original/process-control errors, skip charge release and leave staging files.
- O4: corrupt backup plus rollback failure can abort halfway and leave mixed navigation.
- O5: receipt cleanup can leave a final file after a raised error, blocking retry.
- O6: unknown accelerator types fall through to `cpu_synchronous` without synchronization.
- O7: quarantined revocation event plus deleted derived rows can resurrect evidence.
- O8: post-replace P-pointer failure deletes the newly published record but may leave its pointer live.
- O9: fallback path discards attempted primary-read bytes.
- O10: P reads check revocation only at entry, not after I/O.

These findings require production fixes and focused failure/crash-path tests. Exception-atomic rollback alone is not crash-atomic durability.

The next repair round must address independent rule-family evaluation, all accounting paths, cleanup/original-error preservation, single-authority navigation with restart validation, and explicit MPS-fallback refusal. ## Implementation response

The native development protocol now uses two held-out compound rule families,
`partner_colour` and `same_colour`, with relation/attribute and
equality/attribute composition rather than the retired lookup/revision families.
This addresses the rule-family dependency, but remains only two new families and
one seed—not broad compositional generalization or independent-seed replication.

Density navigation now resolves only through a validated `CURRENT.json`, checks
every canonical file hash, uses `F_FULLFSYNC` on Darwin, and tests process-level
crash/restart resolution. MPS timing requires `PYTORCH_ENABLE_MPS_FALLBACK=0`;
CPU remains the only path used by current density measurements. Multi-file
receipt sets still are not claimed to be SQLite-equivalent power-fail
transactions; `CURRENT` is the sole authority and ambiguous states fail closed.

Producer origin/cleanup reads and writes are accounted, Replica revocation is
revalidated after I/O, and native direct-read bounds follow actual record/site
multiplicity. Independent acceptance review is pending; these changes are not a
native capability claim.

Follow-up: origin creation now has structural artifact allowance and pre-reserved
root/lock/write operations, and unknown compound cases no longer render the
target colour in text. The native focused suite is 92/92 with static environment
and closure review passing; final independent release review is still pending.

Budget follow-up: native accounting now counts both per-world release corpora,
all origin/manifest/pointer bytes, and restart construction. The final probe cap
is 580 (other probes 579), restart 16, probe artifacts 524,288 and restart
artifacts 16,384. The focused native suite is 95/95 with static gates passing;
final independent gate review remains pending.
